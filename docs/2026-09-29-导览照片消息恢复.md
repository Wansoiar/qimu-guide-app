# 导览照片消息恢复

## 问题与范围

用户反馈切后台再返回后，对话中的照片消失。手机上两张原始 AI 拍照文件仍存在，
当前导览也仍活动。源码中照片和本地状态仅进入 `DialogueFragment` 自有的
`SubtitleTimeline`；Fragment 重新创建时只从 `RealtimeGuideManager` 恢复文字字幕。
另外，已初始化设备从 LoginActivity 跳转 MainActivity 使用 CLEAR_TASK，会清除旧页面。
这解释了文件尚在而照片气泡丢失的缺口，不能据此声称每次普通 onPause 都重建页面。

## 修复设计与边界

- 将完整的字幕、照片和本地状态事件统一由当前导览的内存历史持有，视图只读取投影。
  保存原始事件次序，不能把照片和文字分别恢复后简单拼接或按字幕最新更新时间排序。
- 历史按既有 session_id 隔离。同一导览重建页面、RTC 恢复不清空；结束或新导览清空。
  老页面/迟到事件必须携带原导览标识，不能写入新导览。
- LoginActivity 的普通返回入口改为复用已有 MainActivity；初始化与运营登录分支保持原职责。
- 仅保存已有文本和图片 File 引用，不保存 Bitmap、Activity 或 View，也不扫描历史目录
  将没有归属证据的照片补进当前订单。
- 不改变进程死亡后的既有“结束上次订单”策略，不新增跨进程恢复、网络接口、数据库、
  鉴权或媒体删除行为；保留已有 30 秒拍照接收修复。

## 验证

用真实 DialogueFragment 和 RecyclerView 注入已接收照片，分别验证退后台/恢复、
Activity 重建、同导览关闭并重新打开页面。用 JVM 测试验证图文顺序、重复字幕更新、
同导览保留、新导览隔离和旧事件拒绝。先运行旧代码以确认回归用例能检出照片丢失，
再运行修复后的构建、测试和 lint。设备安装和现场回后台验收单独记录。

实际结果：

- 旧代码运行 3 项 Fragment 测试：普通暂停/恢复通过，Activity 重建与重新打开页面均失败，
  照片气泡从 2 张变成 0 张。
- 修复后在 Android 35 模拟器运行同样的 3 项生命周期测试及 1 项真实启动入口复用测试，
  4 项全部通过。测试只注入已接收照片，不连接眼镜或调用后端。
- `assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug` 通过；
  113 项 JVM 测试，lint 0 error、184 warning。单独补齐测试夹具的中断状态清理后，
  重新构建测试包并执行上述 4 项设备测试。
