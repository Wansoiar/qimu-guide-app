# RTC 恢复复用与静默恢复设计

2026-09-24 本地验收记录：设计已评审，跨端 API 已实现，App JVM 回归与开发环境 Debug 构建通过。工作分支 `codex/ysc-phase1-app`，初版基于 `main@a40ad84`；随后合入 `main@b775906`，集成说明见文末。本记录区分初版验证与 main 集成验证。

## 目标

用户确认：短断线尽量无感，恢复成功不弹提示、不再次播欢迎词。旧 Agent 仍可用时复用，不能把业务 session_id 没变等同于 RTC 任务复用。持续中断才显示连接问题，并区分网络与 AI 服务异常。

本次处理连接恢复、原房间重进、Token 续签和必要重建。不新增业务实体。初版不新增锁屏服务；合入 main 后保留其 `GuideForegroundService` 与 BLE/音频中断续接，统一使用下述收音意图，用户主动暂停、导出互斥和录音权限优先。

## 已确认根因

- 修复前 `scheduleRtcReadyTimeout` 使用 20 秒超时，随后 `handleRecoverableRtcFailure` 销毁 SDK、清空 RTC 信息，500ms 后重新请求 `/v1/rtc/session`。
- 修复前创建接口每次创建新 room/uid/task 并停止旧任务，新的 StartVoiceChat 带 WelcomeMessage，因此恢复后可能重播开场白。
- 修复前 App 没有原房间重进阶段，手动重试也先停旧 Agent；`onTokenWillExpire` 被直接当成已过期，停止本地和后端任务。
- 已核验本地 RTC SDK 3.60.105.3500 AAR：引擎连接状态、现代及旧房间状态回调、原房间 join、继承的 `RTSRoom.updateToken(String)` 均可用。实现接入上述能力。
- 锁屏/页面暂停没有直接停止 RTC；实际发生哪个断连回调还需真机日志，不能断言所有锁屏都会重建。

## 本地状态机

新增无 Android 依赖的 `RtcRecoveryController`，只管理阶段、原因、单调时钟期限、恢复轮次和用户收音意图。SDK/HTTP/音频动作仍由 `RealtimeGuideManager` 执行。

| 阶段 | 动作 | 成功条件 | 超时/失败 |
|---|---|---|---|
| 在线 | 沿用原 RTC/Agent | 正常服务 | 临时中断进入等待 SDK |
| 等待 SDK（20 秒） | 保留 SDK 与所有会话身份；关闭上行，等待原连接恢复 | 本端房间恢复，目标 Agent 的新在线证据到达 | 尝试原房间重新进房 |
| 原房间重进（20 秒） | 只释放本地 SDK，保留 room/uid/task/token；新本地 generation 后 join 原房间；不调后端 start/stop | 本端进房且收到当前 botUid 的新在线证据 | 才允许请求替换任务 |
| 必要重建 | 请求带旧任务证明的创建接口，静默启动新 Agent；网络/502/40911 最多 3 次相同请求，间隔 1 秒、2 秒 | 新房间及 Agent 就绪 | 新任务进房仍限 20 秒；每轮中断最多替换 3 个任务 |
| 终止 | 停止恢复，取消所有延迟/异步后续 | 无 | 不自动复活 |

重复 SDK/房间/Agent 回调不重置同一阶段 deadline，也不增加创建次数。永久错误（封禁、踢出、重复登录、明确鉴权/许可错误）终止，不当作网络波动重建。

新旧房间回调统一归一；重复回调不会重置期限。`RtcFailurePolicy` 依据本地 SDK 已知错误常量分类 Token 错误与权限、踢出、重复登录、许可等永久错误；现代 reason 同样分类，未知故障使用中性原因。SDK 断连回调先关闭 PCM gate，再通知主线程。

原房间重进必须清除旧 `agentOnline` 快照，再等待本次 botUid 在线证据；不能把后端 DB active 当作实时存活证明。

## 显示与收音意图

- 使用 **3 秒**问题提示阈值；短断连保留断前状态文案和指示点，不加 toast 或对话气泡。内部立即关闭 PCM/拍照 gate，防止对未就绪连接操作。
- 持续中断根据证据显示：“网络连接暂时中断，正在恢复…” / “AI 导览服务暂时未响应，正在恢复…”；证据不明时用“连接暂时中断，正在恢复…”。
- 恢复后还原原状态，不显示“恢复成功”、不播欢迎词。
- 断前 LISTENING 才能自动恢复收音；仍复核录音权限、眼镜连接、媒体传输 busy。断前 PAUSED 不自启麦克风。
- 恢复期间用户主动暂停、开始导出或录音权限不可用会撤销收音意图，优先于断线前旧意图。合入 main 后，眼镜临时断开只关闭收音，保留续接意图；重新连接后仍须满足 RTC、权限及导出门禁。
- 新任务的欢迎音频必须后端启动配置抑制；只隐藏 App 欢迎字幕不满足要求。
- 终止错误的对话按钮显示“前往结束导览”，导航现有导出页，由原有确认流程结束。该错误不锁住导出/结束入口，不自动归还或清理照片。

## Token 与异步 fencing

Token 到期前 60 秒和 SDK 预过期回调触发续签；预过期临时失败不拆掉有效连接。续签响应必须匹配当前 tour + room + task + uid、SDK generation 和续签 ticket；旧回包不能覆盖新 Token。`RtcTokenRenewalController` 防重复预过期回调：每窗口最多 3 次 HTTP 尝试，失败等到期，再给一次 120 秒宽限内的补试窗口；原房间重进不会恢复已用掉的宽限预算。

结束游览、开始归还或进入终止阶段后，所有恢复定时器、续签回包、创建回包失效。释放本地 SDK与停止后端 Agent 必须分开；只有主动结束、永久失败或明确替换任务才停止后端。复用路径不能套用“迟到创建响应直接 stop Agent”的旧清理逻辑，否则可能误停仍在使用的旧任务。

已实现的 API：

- 首次 `POST /v1/rtc/session`：`session_id` 加 `initial_only=true`。可取回尚未重建过的现存首任务，正在启动返回 40911；拒绝复活已结束导览，覆盖“退出先到、创建后到”。恢复重建必须带 `previous_task_id/room_id/uid/token`，不传 `initial_only`；同前驱重试返回相同直接后继任务。两条路径的临时失败都最多尝试 3 次，App 不用首次入口代替有证明的恢复。
- `POST /v1/rtc/session/renew-token`：`session_id/task_id/room_id/uid/token`，原 join token 是持有证明；返回同四项身份、Token 与 Unix 秒 `expire_at`。
- 40310、40401、40910 和 HTTP 401/403 终止当前恢复，明确要求重新开始导览；40911、HTTP 408/429/5xx、网络失败和兼容业务码 502 可有界重试。旧服务端不支持续签时保留仍有效的连接，到期给明确错误，不盲目重建。
- `/session/stop` 的 `end_session=true` 用于结束/退出，`false` 用于迟到或孤儿任务清理。迟到幂等响应若等于已附着当前任务，不发送清理。首次创建还未返回 room/task 就退出时，仅发送 `session_id/end_session=true`，不发空字符串，后端锁内关闭当前/正在启动的任务。
- 主动结束和 crash 在清空 Tour 前捕获公参 Header，异步停止不会丢掉手机号。合入 main 后，按 Home、Activity 退出或划掉最近任务由前台服务继续托管，不视为结束导览。重启沿用现有产品：内存 Tour 不恢复，`active_marker` 转为清理告警，设备页先“结束上次订单”再开始；遗留 room/task 缺失时使用 session-only stop。后端对该只结束分支要求设备/眼镜归属，允许省略已不可恢复的手机号；App 没有增加个人信息持久化。
- 主线程在入队前捕获 HTTP cancellation epoch；退出后才登记的旧请求同样被拒绝。RTC 使用独立的恢复执行器，不排在图片上传之后；HTTP 超时 25 秒。RTC 日志仅 BASIC，不打印 Header、请求体或响应体中的凭证。

部署顺序后端先、App 后；跨仓契约见 `ai-guided/docs/development/2026-09-24-身份拍照与RTC恢复修复设计.md`。

## 本地回归结果

使用虚拟单调时间验证生产 controller 的动作和失效 ticket；API 测试使用生产请求字段、响应校验、错误分类、HTTP 取消登记和日志配置：

1. SDK 在期限内恢复：零次原房 join、零次后端创建/停止。
2. SDK 超时后原房恢复：仅一次本地 join，room/uid/task 不变，零次后端创建/停止。
3. 原房恢复失败后重建：恰好一次创建；重试次数与阶段 deadline 有界。
4. 问题提示 3 秒边界、网络/服务/未知原因映射；恢复成功不发成功提示。
5. 重复和乱序回调不延长期限，旧 generation/attempt 不触发动作。
6. LISTENING/PAUSED 意图、恢复期间主动暂停/导出与眼镜连接门禁；权限或 busy 门禁不被绕过。
7. Token 预过期只续签，旧任务或旧 attempt 回包不 updateToken、不恢复旧任务。
