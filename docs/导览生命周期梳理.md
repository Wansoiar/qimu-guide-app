# 导览生命周期：从点击「进入导览」到结束会话

> 口径：只看「导览」这条线——建会话、建房、结束。对话期间的收音/字幕/识图技术细节一律略过。

2026-09-24 更新 RTC 恢复、Token、字幕和拍照门禁；未更新段落中的历史行号仅作旧版定位参考。

## 一、全景

这条链路横跨 5 个文件、3 个页面 + 2 个后台对象：

```
设备页「进入导览」→ 前台服务启动 → TourSessionManager 建会话（持久化）
  └→ GuideForegroundService → RealtimeGuideManager.startForTour → 建 RTC 房 + 起 Agent
对话页「开始对话」→ startGuidance → SCO 收音 → 16k PCM 注入 RTC 上行
  └→ AIGC 字幕/下行回包 → 气泡合并上屏
导出页「结束游览」→ TourReturnCoordinator.beginReturn → stopForTour(退房+停 Agent) + 关会话 + 擦眼镜 + 清本地
```

关键设计前提：**RTC 属于整次游览**；「开始对话」打开眼镜麦克风，「暂停」只关收音且仍可能计费。短时断连优先恢复现有连接，随后只重建本地 SDK 重进原房；确实失败才替换 Agent。用户结束和永久失败会执行相应停止。

## 二、点击「进入导览」（设备页）

**入口** `DeviceFragment.java:203` `btnStartTour.setOnClickListener → beginStartTourFlow()`。

`beginStartTourFlow()`（229）三道闸：
- `isActive()` 已有会话 → return；
- `hasCleanupWarning()` 有残留清理告警 → toast 拒绝；
- 眼镜未连接且非 DEBUG → `autoReconnectLastDevice()` 等重连（243-247）。

连线成功后 `showOrderDialog()`（251）：输入订单号 + 隐私同意勾选（`privacy_consent_checkbox`）→ 确认 → `createTourSession()`（376）。

`createTourSession()`（376-452）：
1. `beginSessionRequest()`（385）— TourSessionManager.java:73 用代际号 gate：已有会话/有告警返回 -1。
2. 取 `ANDROID_ID` 作 deviceId（394）。
3. DEBUG 且订单号为 mock → 本地 UUID 直接 `postSessionCreated`（400）。
4. 否则要求眼镜在连接态（408），然后 `TourSessionApiClient.createSession(orderNo, venueId, deviceId)`（418）→ 成功回调 `postSessionCreated`。

`postSessionCreated()`（454）→ **`beginSession()`（474）**，即 `TourSessionManager.java:88`：
- 校验 `isSessionRequestCurrent`（93，代际号仍有效）→ 创建 `TourSession` 内存对象 + `SharedPreferences active_marker=true`（100-105）→ **`notifyListeners(true)`**（106）。

用户确认后先启动 `GuideForegroundService`；后端会话创建成功时由服务接收
`onTourSessionChanged(true)`，再调用 `RealtimeGuideManager.startForTour(session)` 建 RTC 房。
`MainActivity` 只负责切换到对话页，不再拥有后台会话生命周期。

## 三、RTC 进房（startForTour）——点「开始对话」前的后台准备

`RealtimeGuideManager.startForTourOnMain`：
1. 归还流程中、会话不是当前、同 session 已在连接/使用时均不重复创建。
2. ERROR 仍持有 RTC 身份时走原任务重试；鉴权/任务终止错误要求重新开始，不清空证明后盲建。
3. `generation` 使旧回调失效；新 Tour 清字幕、工具指令去重和恢复状态。
4. 注册 BLE 监听，进入 `RTC_CONNECTING`，首次请求带业务 `session_id` 和 `initial_only=true`，迟到首次请求不能复活已结束导览。
5. `onRtcSessionCreated` 保存 room/task/uid/token/expire_at 和 bot_uid，记住供退出清理的 room/task，再建本地 SDK。旧响应仅清理未附着的任务，使用 `end_session=false`。
6. 进房等待纳入有界恢复控制器，同时安排 Token 续签。

`RtcVoiceChatManager.start`（101）的核心：
- `stop()` 清上次残留（103）；
- 建 `RTCEngine`，场景 **AICLIENT**（122），下行 **外部渲染**（`EXTERNAL`，126）+ `setPlaybackVolume(400)`（129）——这是绕开「下行被媒体流压低到 ~0.0075」的解法链，见类注释 123-130；
- 上行用**外部音频源**（131）+ 10ms `framePump`（147）；
- 启动 `RtcDownlinkVoicePlayer` 独占 `VOICE_CALL` 流播放（150）；
- `createRTCRoom` + `joinRoom`（152-166）。

**进房就绪判定**：本端 RTC 进房和目标 Agent 新在线证据都完成才就绪；中断及原房间重进清除旧 presence。恢复按 `SDK_WAIT 20s → 原房间重进 20s → 最多 3 次受证明保护的任务替换`；SDK/原房间成功不调用后端 Start/Stop。中断 3 秒内保留原状态，之后显示网络、Agent 或未知连接问题；成功还原 READY/PAUSED/LISTENING 意图，不提示成功。详情与验证边界见 [RTC 恢复复用设计](2026-09-24-RTC恢复复用设计.md)。

## 四、点击「开始对话」（对话页）→ 打开收音

**入口** `DialogueFragment.java:170` `dialogueButton → handleDialogueButton()`（192）：
- `READY / PAUSED` → `startGuidanceWithAudioPermission()`；
- `LISTENING / AUDIO_LINK_STARTING` → `pauseGuidance()`（暂停）；
- `ERROR` → `retryCurrentTour()`。

权限前置（210-232）：已授权直接 `startGuidance()`；没授权则走 rationale 弹窗/系统授权，授权回调里再 `startGuidanceIfReady()`（77）；从系统设置页返回在 `onResume`（588）再补一次。

`RealtimeGuideManager.startGuidanceOnMain`（426）门禁：
- `state` 必须 READY/PAUSED（427）；
- 不在照片导出 hold 中（428）；
- **`rtcRoomJoined && (mocked || agentOnline)`**（433）；
- 眼镜仍在连接（440）；`rtc` 非空（445）。

通过后：
1. `currentRtc.setInputEnabled(false)` 先关上行门（452）；
2. `state = AUDIO_LINK_STARTING`（453）；
3. `glassesAudioSource.start(...)`（454）——`ScoMicAudioSource.java:74`：
   - `MODE_IN_COMMUNICATION` + `startBluetoothSco` + `setBluetoothScoOn(true)`，**通话音量拉满**（96-116，否则眼镜里 AI 声音小到听不见）；
   - 轮询等 SCO 连上（119，250ms 间隔、4s 超时）→ `beginRecording`：`AudioRecord(VOICE_COMMUNICATION, 16k, mono)`（138-147）；
   - 录音线程每 20ms 吐一块 PCM（174-196）。
4. `onStarted`（454-477）：代际/attempt 校验 → `setInputEnabled(true)`（469）→ `routeToBluetooth()`（473）→ `setGlassesVolumeMax()`（474）→ **`state = LISTENING`**（475）。
5. 兜底 8s 超时：还在 `AUDIO_LINK_STARTING` 就回 `PAUSED`（498-508）。

**上行链路**（聊天核心）：
`ScoMicAudioSource.onPcm`（480-485）→ 仅 `LISTENING` 时 `rtc.pushExternalPcm(pcm)` → `RtcVoiceChatManager.pushExternalPcm`（174）：按 **10ms 重帧**（320 字节）塞进 `pcmFrames` 队列（队列上限 50 帧=500ms，满则丢最旧，187-191）→ 每 10ms `framePump` 弹出 → `pushExternalAudioFrame`（302-320）注入 RTC 上行。

## 五、对话进行中（字幕回显 + 下行音频）

**AI 字幕有两条回调链路**（`RtcVoiceChatManager`）：
1. `onSubtitleMessageReceived`：SDK 字幕，当前 SDK 的 `SubtitleMessage` 不提供 `roundId`，标记来源为 SDK；
2. `onRoomBinaryMessageReceived` → `parseAigcBinary`：火山 VoiceChat `subv+JSON` TLV 字幕，解析 `data[]` 的 text/speaker/definite/`roundId`（兼容 `round_id`），标记来源为 BINARY。`BinarySubtitleTracker` 为无序号的 interim/final 分句维护稳定序号，已知轮次变化时更换序号。`subv` 之外：
   - magic 含 `tool` → FC 拍照指令；
   - magic 含 `info` → 忽略；
   - 其他 → `onCommand` 控制协议。

`RealtimeGuideManager.createRtcListener.onSubtitle` 保留过程引导语过滤和旧 RTC 实例回调门禁，把 generation、source、roundId、sequence、单调时钟接收时间传入 `SubtitleTranscript`。后者仅保存 final；同来源相同事件幂等，跨来源在 1.5 秒内匹配同房间代次/连接边界、同说话人、已知轮次兼容且同文本的事件。两个已知不同轮次或同来源新 sequence 不会因为重复用语被吞掉。SDK 先到后，匹配到的 subv 会补齐轮次并通知 UI 重新投影。

`DialogueFragment` 的实时事件与 `getTranscriptSnapshot()` 回放统一进入纯 Java `SubtitleTimeline`：
- 已知轮次按 generation + 连接边界 + speaker + roundId 归并；同轮多句合并，跨轮、跨重连不合并。乱序旧轮 final 更新原轮气泡；同来源句子按 sequence 排序。
- 无 roundId 的连续分句按说话人、10 秒静默/45 秒最长片段降级分段；已知轮次不受这两个超时影响。后续补全 roundId 会重算气泡。
- 照片、拍照状态和本地错误形成显式视觉分隔，后续字幕留在照片之后。
- 重连在管理器 transcript 和底层 binary tracker 同时重置分组/去重边界；新 RTC 实例仍用 generation 拒绝旧回调。

完整设计、协议信息缺失时的限制和本地回归范围见 [一期字幕与拍照配置修复](2026-09-24-一期字幕与拍照配置修复.md)。这项修复不改变锁屏音频/进程保活。

**下行音频**：`RtcDownlinkVoicePlayer` 从 RTC 外部渲染拉流，用 `STREAM_VOICE_CALL`（通话流）AudioTrack 播到蓝牙，避开媒体流被通话场景压低的问题（类注释 123-130、216）。

**打断**：SCO 全双工，讲解时收音仍在采集，游客开口即上行打断（`ScoMicAudioSource.java:22-26` 注释，替换旧 BLE Translation 通道的原因）。

**拍照场馆配置**：一期已移除 `photo_enabled` 的 App 解析和消费，旧后端返回 false 也不再禁用拍照；会话就绪、眼镜连接、硬件忙闲/下载互斥、任务预留及现有用户授权链仍保留。

**拍照识物旁路**（用户没点名但同链路）：模型 `take_photo` FC 指令 → `handleFunctionCall`（1177）→ `pendingVisionRequest` → `deliverPendingVisionRequest`（1208）→ Fragment `onVisionCaptureRequested` → `connection.takePhoto(ModeAIRecognition)` → 图片回 `injectVisionImage`（694）→ upload + describe-image（737-773）→ func 回填/文本注入 → 模型继续讲解。中间态用 `generation/visionOperationId` 防旧任务回包。

## 六、暂停 / 继续

- **暂停**：`handleDialogueButton` 里 `LISTENING/AUDIO_LINK_STARTING → pauseGuidance`（200）→ `pauseGuidanceOnMain`（599）：`setInputEnabled(false)` + `glassesAudioSource.pause()`（SCO 保留、只停采集，`ScoMicAudioSource.java:202`）→ `PAUSED`。**RTC 和 Agent 仍在线（≠ 停止计费）**——这是刻意设计（注释 511）。
- **继续**：按钮态 `PAUSED → startGuidance` 走第四节同样的链路（SCO 已在，恢复快）。
- **系统短暂抢占**：提示音、导航播报或短暂通话触发 `AUDIOFOCUS_LOSS_TRANSIENT(_CAN_DUCK)` 时只暂停 PCM 并保留用户的收音意图；收到 `AUDIOFOCUS_GAIN` 后自动重建收音。永久失去焦点才停止并要求用户手动继续。
- 眼镜断开会自动 `pauseForGlassesDisconnect` 停收音，不退房；保留原有收音意图，BLE 恢复后经 RTC/权限/导出门禁自动续接。用户可在临时暂停期间取消续接。
- 恢复期间按钮可修改继续/暂停意图；权限、眼镜连接和媒体导出状态在自动恢复前再次核验。用户暂停与导出优先于断线前 LISTENING，旧音频回调不能重开或暂停后来一次收音。

## 七、点击「结束游览 = 对话结束」（导出页）

**入口** `ExportFragment.java` `btnEndTour → confirmEndTour()`（805）：
- 眼镜未连接 → 「跳过检查」分支（812-821）；
- 连上则 `queryNewMediaFile` 查剩余照片（827）→ `handleEndMediaCount`（832）：「眼镜上还有 N 张未导出照片」弹窗 → 先导出 or 直接结束；
- `showFinalReturnConfirmation`（851）确认 → **`beginIrreversibleReturn()`**（864）。

`beginIrreversibleReturn`（864）：先**移除对话 tab**（865-869，没收尾 Fragment），禁用导航，显示「正在结束导览」进度 → **`returnCoordinator.beginReturn()`**（872）。

`TourReturnCoordinator.beginReturn` 当前按“冻结 → 确认 → 清理”执行，详细边界见 [结束游览确认整合](2026-09-25-结束游览确认整合.md)：

1. 主线程检查活动会话及归还占位，锁定眼镜与媒体目录，并失效待创建业务会话请求。
2. `prepareServerStopForTour` 捕获 session、RTC 身份和公参 Header，立即冻结收音、RTC 引擎、拍照、恢复/续签及迟到回调；尚未收到建房响应也必须结束对应 session。
3. 独立客户端确认 `/v1/rtc/session/stop`，携带 `end_session=true`。HTTP 调用、重试等待与 UI 共享从确认开始计算的 20 秒绝对截止时间，每次请求使用剩余预算，快速失败最多重试 3 次。只有在截止前收到 HTTP 成功、`code=0` 和明确 `stopped=true` 才通过。
4. 失败保留订单、字幕及媒体文件，关闭进度并显示重试原因；保持 RTC 停止状态，不自动恢复对话。超时、重复、旧操作回包不能进入清理。
5. 成功后 `completeConfirmedServerStop` 清理本地 RTC 状态，不重复发送后端停止请求，再执行眼镜 reset 和本地媒体清理。

归还后续回收：
- `startGlassesReset` → `resetForReturn` 擦眼镜 → `cleanupLocalData` 删除会话目录、音频缓存、相册、选择状态和 SDK 媒体目录，保留既有路径边界校验。
- `finish` 将眼镜 reset 与本地清理的实际结果交给 `completeSession`，未完整清理则保留告警并阻止下一位游客开始。
- `prepareForNextVisitor` 复位连接状态并广播完成；`GuideForegroundService` 在完整归还结束后移除通知并释放 WakeLock。
- “结束上次订单”走相同确认与清理管线；缺少完整 room/task 时发送 session-only stop，失败不清除上次订单标记。

活动导览和上次订单的进度、成功及失败回调分别由导出页和设备页展示。前台服务在确认失败时更新提示、释放确认阶段的 WakeLock。崩溃的尽力收尾仍使用原有异步 stop 路径；原房重进只替换本地 SDK，不走归还清理。

## 八、后台持续与异常退出

- 锁屏、按 Home、Activity 销毁或划掉最近任务：不结束导览，`GuideForegroundService` 继续托管；
- 用户点击「开始对话」后，服务升级为 `microphone|connectedDevice` 前台类型，SCO/RTC 在锁屏后继续；
- BLE/RTC 临时断开：保留用户的收音意图，连接恢复后自动续接；
- 用户显式点击「结束本次游览」：走完整归还流程后停止前台服务；
- 进程崩溃或被系统杀死：不静默恢复麦克风，沿用 active marker 与清理告警兜底。

## 汇总：全程接口 & 落盘清单

**HTTP 接口（本次范围）**

| # | 端点 | 时机 | 请求体要点 |
|---|---|---|---|
| 1 | `POST /sessions` | 开始导览 | order_no, venue_id, device_id |
| 2 | `POST /v1/rtc/session` | 建房 | venue_id, session_id(复用), 眼镜MAC, 手机device_id |
| 5 | `POST /v1/rtc/session/stop` | 结束确认/退出 | session_id、end_session=true；room_id/task_id 成对可选 |

**状态落盘（SharedPreferences `tour_session_state`）**

| 键 | 写点 | 值 |
|---|---|---|
| `active_marker` | beginSession→true；completeSession→false | 会话是否在途（重启恢复的依据）|
| `session_id` | beginSession 写入；completeSession 移除 | 在途会话 id |
| `cleanup_warning` | beginSession→false；completeSession→ !cleanupConfirmed；异常退出→异常值 | 是否需要管理员先确认清理 |

**内存状态（进程内）**：`TourSessionManager.session`、`RealtimeGuideManager` 的状态/`rtcSession`/transcript、恢复阶段/意图/ticket、Token 续签 ticket，以及 `RtcVoiceChatManager` 的 engine/room。业务 session_id 与 RTC task/room 并非同一身份。

**非 HTTP 动作**：BLE 擦眼镜（resetForReturn）、前台 Service 启停（GuideForegroundService）、本地文件删除（会话目录/音频缓存/SDK 媒体/相册）。

---

结束链路统一通过 `/v1/rtc/session/stop` 的 `end_session=true` 关闭 RTC 与业务订单，不再调用独立的 `/sessions/{id}/close`。
