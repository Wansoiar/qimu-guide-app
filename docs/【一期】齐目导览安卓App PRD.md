> 5. **归还流程**：结束游览时先查眼镜端是否有未导出照片（`queryNewMediaFile`），有则弹窗提醒；最后统一 reset 眼镜（`CRPBleConnection.reset()` 是清眼镜端媒体的唯一手段）。不主动 unbind，下位游客开机后 BLE 自动回连。

## 1. 产品概述

### 1.1 定位

「齐目导览」Android App 是 AI 智能导览系统的 C 端载体，预装在投放手机中，无账户概念。游客在博物馆/景区现场自行完成取眼镜 → 连接眼镜 → 拍照/语音提问 → 听讲解 → 导出的完整体验。

### 1.2 核心功能

游客通过**按眼镜左键**主动进入对话模式（无端上唤醒词），然后开口说话提问。App 收流做 ASR 实时转写，并在**转写结果里做关键词匹配**（如"帮我看看眼前"/"这是什么"）以触发眼镜拍照识别。AI 讲解词通过眼镜耳机播报，并在 App 屏幕以文字呈现。每个 AI 讲解气泡都带有重新播放按钮。

**导出流程分两段**，两段都在**导出 Tab**（Tab 3）里，游览中可多次触发：

- **段 1 · 导出照片到本机**：点【导出眼镜照片】→ WiFi 建连 → 眼镜原图下载到 App 本地会话目录
- **段 2 · 生成二维码**：点【生成二维码】→ 挑选（默认全选本地池）→ 输手机号 → 并发上传服务端 → Tab 3 上展示二维码

**结束游览**：点【结束游览】→ 查眼镜端未导出数量 → 有则弹窗询问是否先导出 → 最终 `CRPBleConnection.reset()` 清眼镜 + 清 App 本地 + 关闭 session → 回挂牌页。App 端不主动 unbind，眼镜重启后 BLE 自动回连，方便下位游客点【开始游览】直接使用。

### 1.3 无账户模型

- App 预装在投放手机中，无登录/注册
- 每次使用以单次会话（session）为唯一标识
- **每位游客都必须先点「开始游览」**，由服务端**每次生成一个全新 session_id**，用来隔离不同游客的对话上下文、照片、分享包
- 会话内的照片、对话上下文都绑定到该 session_id
- 会话中游客可在**导出 Tab 主动生成二维码**（可多次），每次生成产生一份**分享包（share bundle）**——用**手机号后 4 位**做扫码验证，7 天有效
- 手机号仅用于分享包扫码验证，**不建立用户体系**、App 端不保存

### 1.4 用户操作路径

```
打开 App（挂牌页 = 设备 Tab 的"未开始"状态）
→ 眼镜自动回连（上一位游客 reset 后眼镜重启，App 未 unbind，BLE 自动回连）
→ 游客点【开始游览】（设备 Tab 内）
→ 弹窗输入订单号（租赁柜订单号，管理员/游客手输）
→ 眼镜已连接 + 订单号非空：POST /sessions（带 order_no + venue_id + device_id）
   → 拿到 session_id → 自动跳到对话 Tab
   → 眼镜未回连：按钮转 Loading 等回连（订单号已输入的话保留）
→ 对话 Tab（首次进入会全屏弹一次使用教程，见 §3.4）
  ├─ 按眼镜左键 → 说话 → App 收流 ASR 转写
  │   ├─ 转写文字含拍照关键词（"帮我看看眼前是什么" 等）→ 触发眼镜拍照 → AI 识图讲解
  │   └─ 转写文字为普通问题 → AI 文本回答 + TTS 讲解播报
  └─ 每个 AI 气泡可重播
→ 游客可随时切到 导出 Tab：
   ├─【导出眼镜照片】→ WiFi 拉眼镜原图到 App 本地（第 1 段）
   ├─【生成二维码】→ 挑选 → 手机号 → 上传 → 二维码（第 2 段）
   └─ 二维码显示在 Tab 3，切回对话 Tab 后再切回来仍在
   （两段操作独立，游览中可多次；每次生成都是独立分享包，服务端 7 天有效）
→ 【结束游览】（导出 Tab 底部）
   → App 调 queryNewMediaFile 检查眼镜端
   ├─ 眼镜端有未导出：弹窗"眼镜上还有 X 张未导出，是否先导出？"
   │   ├─ [先导出] → 强制走"导出到本机" → 询问"要生成二维码吗？"
   │   │            → 如需要则走"生成二维码" → 归还
   │   └─ [直接结束] → 归还（未导出图会被 reset 清掉）
   └─ 眼镜端无未导出：二次确认 → 归还
→ 归还收尾：reset 眼镜 + 清 App 本地 + close session → 回挂牌页
```

### 1.5 页面一览

| 页面 | 类型 | 未开始游览 | 已开始游览 |
|------|------|-----------|-----------|
| **设备** | Tab 1 | 眼镜连接状态卡 + 【开始游览】按钮 | 设备信息卡（电量/信号/固件/连接时长） |
| **对话** | Tab 2 | 灰显（提示"请先开始游览"）| 对话流 |
| **导出** | Tab 3 | 灰显（提示"请先开始游览"）| 导出/生成二维码/结束游览 |

> **说明**：v2.3 保持 3 个 Tab。挂牌页不再是独立页面，而是**设备 Tab 的"未开始游览"状态**——启动时默认落到设备 Tab，看到的就是"挂牌页"内容（Logo、场馆选择、眼镜连接卡、【开始游览】大按钮）。
>
> **【开始游览】**放在设备 Tab —— 与"确认眼镜已连接"是同一语义组，游客的注意力自然聚焦在"眼镜准备好没有"。
>
> **【结束游览】**放在导出 Tab —— 结束前的最后一件事往往是"再确认一下有没有想带走的照片"，把导出与结束放在同一个 Tab，动线自然（想结束 → 到导出 Tab → 顺带看一眼要不要导出/生成二维码 → 结束）。

## 2. 设备 Tab

设备 Tab 是 App 启动后的默认落地页，也是承载**开始游览**入口的核心页面。按会话状态分两种：

- **未开始游览**（挂牌页形态）：Logo、场馆选择、眼镜连接状态、【开始游览】大按钮
- **已开始游览**（设备信息卡形态）：设备实时状态展示（电量、信号、固件、连接时长）

对话 Tab 与导出 Tab 在"未开始游览"时**灰显**，点击时提示"请先开始游览"。

---

### 2.1 未开始游览（挂牌页形态）

**布局元素**（自上而下）：

| 元素 | 说明 |
|------|------|
| Logo + 名称 | 品牌展示 |
| 当前场馆卡片 | GPS 自动定位，显示场馆名 + 下拉切换按钮 |
| 眼镜连接状态指示 | 大号状态卡：🟢 眼镜已连接 / 🟡 正在连接眼镜… / ⚪ 未检测到眼镜 |
| 【开始游览】主按钮 | 深棕金色实心大按钮；创建 session 并跳到对话 Tab |
| 上一位归还异常告警条（如有）| ⚠️「上次归还未完成清理，请管理员检查眼镜」；同时 【开始游览】临时禁用 |

#### 2.1.1 场馆选择

- App 启动后通过手机 GPS 定位获取当前位置
- 服务端返回附近场馆列表，自动选中最近场馆
- 用户可点击场馆名展开下拉列表手动切换
- 未选择场馆时【开始游览】灰显
- 场馆影响后续所有 AI 检索的知识库范围

#### 2.1.2 眼镜自动回连

**背景**：上一位游客归还时 App 会向眼镜发 `reset()` 命令；眼镜重启，但归还流程**不主动 unbind**（不解除"眼镜-App"的配对关系），因此重启完成后 BLE 会**自动回连**本机 App，无需管理员干预。

**App 侧行为**：

- `BleService` 常驻监听连接状态
- 眼镜从"断开 → 连接中 → 已连接"整个过程实时更新状态卡颜色
- 首次自动回连成功后，App 静默完成 BLE 内部握手（`syncTime`、`queryBattery`、`queryDeviceVersion`），不打扰游客

#### 2.1.3 【开始游览】流程

**Step 1 · 点击按钮**（按眼镜连接状态分支）：

| 眼镜状态 | 按钮 UI | 点击后 |
|---------|--------|-------|
| 🟢 已连接 | 深棕金色实心，可点 | 立即弹出订单号输入弹窗（Step 2） |
| 🟡 正在回连 | 按钮显示 Loading「正在连接眼镜…」 | 后台等回连成功事件（最多 15s），成功后弹出订单号输入弹窗；超时见 E-16 |
| ⚪ 未连接（超 20s 无回连） | 按钮变【重试连接眼镜】 | 点击后触发 BLE 主动扫描（走 §2.1.4 手动连接兜底流程） |

**Step 2 · 输入订单号弹窗**（模态弹窗，不可退出）：

| 元素 | 说明 |
|------|------|
| 标题 | 「请输入订单号」 |
| 说明文字 | "在租赁柜取眼镜时提供的订单号" |
| 输入框 | 单行文本框，非空校验；一期不做长度/格式校验，仅前后端 trim 空格 |
| 【取消】按钮 | 关闭弹窗，回设备 Tab；不创建 session |
| 【确认】按钮 | 输入框非空时可点；点击后触发 Step 3 |

一期不做格式校验，具体规则由后端补充后再收紧。

**Step 3 · 创建 session**：

- `POST /sessions` 请求体带 `order_no`（Step 2 输入）+ `venue_id`（GPS 场馆）+ `device_id`（本机 SN/Android ID）
- 响应返回全新 `session_id`，App 保存到内存，后续所有对话/上传请求都带这个 ID
- 服务端可能返回业务错误（如订单号不存在、订单已关闭、订单已绑定其他 session）→ Toast 显示后端消息，弹窗保持展示让游客改（见 E-17a）
- 网络异常/5xx → Toast「创建会话失败，请重试」，弹窗保持展示

**Step 4 · 跳转对话 Tab**：Session 创建成功后自动切到对话 Tab 3.x，游客看到"🟢 已就绪，按眼镜左键说话"提示。

**为什么【开始游览】是必须的独立步骤**：

- **隔离不同游客**：每位游客独立 session_id，服务端能区分对话上下文、知识库检索范围、分享包归属
- **绑定订单**：session_id ↔ order_no 一对一，方便运营侧追账/售后
- **意图起点**：点击 = 游客声明"我要开始了"；之后拍照/说话才计入本次会话
- **与 reset 后自动回连解耦**：BLE 回连是硬件层事件，可能发生在游客拿到手机之前或之后；用一次显式点击把两条时间线在这里收敛

#### 2.1.4 手动扫描连接（兜底）

正常路径下眼镜会自动回连，但极端情况（眼镜被断电、蓝牙缓存失效等）需要手动扫描：

- 状态卡下方隐藏折叠一个【手动扫描连接眼镜】小字链接，默认不显示
- 眼镜"⚪ 未连接"状态超过 20 秒时才显示这个链接
- 点击后展开扫描列表（沿用原 §3 设备管理页扫描连接流程）：
  - 扫描（15s 超时）→ 发现设备列表（名称 + MAC + RSSI）
  - 用户选中一个 → 发起连接（10s 超时）
  - 连接成功 → 折叠回收扫描列表 → 状态卡变 🟢

### 2.2 已开始游览（设备信息卡形态）

进入对话 Tab 后，设备 Tab 从"挂牌页"变身"设备信息卡"。**顶部不再有"开始游览"按钮**（游览已开始），也**不放"结束游览"按钮**（结束游览在导出 Tab）。

**设备信息卡**：

| 字段 | 数据来源 |
|------|---------|
| 设备名 | 连接时获取 |
| 设备 ID | 连接时获取 |
| 电量百分比 | 眼镜实时上报，持续更新 |
| 信号强度（RSSI） | 实时显示 |
| 固件版本 | 连接时获取 |
| 本次连接时长 | 实时计算，秒级刷新 |

**低电量与断开处理**：

- 电量 < 10% → 顶部黄色警告条 + 电量数字变红
- 电量 ≤ 3% → 强制引导到导出 Tab 结束游览（数据已在 App/服务端）
- 眼镜运行中断开 → 弹窗提示（详见 E-04）

## 3. 对话 Tab

### 3.1 页面结构

| 区域 | 内容 |
|------|------|
| 顶部 | 场馆名 + AI 状态标签（空闲 / 识别中 / 思考中 / 讲解中） |
| 中部 | 对话气泡流（自动滚动到底部，手动上滑时暂停自动滚） |
| 底部按钮区 | 两个手机端备用触发按钮：【🤳 AI 拍照提问】、【🎤 按住说话】 |
| 底部提示语 | "按眼镜左键说话提问，例如'帮我看看眼前是什么'" |

### 3.2 触发对话的三种方式

对话可通过 **1 个眼镜端主入口 + 2 个手机端备用入口** 触发：

| 入口 | 位置 | 使用方式 | 说明 |
|------|------|---------|------|
| **① 眼镜左键**（主推）| 眼镜物理按键 | 短按左键 → 说话 → 松开静默 3 秒结束 | 主要交互方式，无需碰手机 |
| **② 手机 · 按住说话** | 对话 Tab 底部 | 长按按钮说话 → 松开结束 | 眼镜按键失灵/距离手机远时的备用 |
| **③ 手机 · AI 拍照提问** | 对话 Tab 底部 | 单击按钮 → 直接触发眼镜拍照识别 | 无需说话，一键拍照识图 |

**语音处理链路**（入口 ① 和 ② 共用）：

1. 眼镜通过 BLE 推送 PCM 音频流到 App
2. App 端**豆包 ASR** 增量转写（1.5 秒切片、10 倍音量放大）
3. 静默 3 秒判定本轮说话结束 → 拿到完整转写文字
4. 转写文字送入服务端 LLM → AI 回答（TTS 音频 + 文字）
5. **同时**在 App 端做**关键词兜底匹配**：转写文字若含 "帮我看看眼前"、"我眼前"、"我面前"、"这是什么"、"这是啥" 等，即使 LLM 未主动触发拍照，App 也直接调 `takePhoto(ModeAIRecognition)` 让眼镜拍照识图（兼容 LLM 未识别到拍照意图的场景）

> **⚠️ 无端上唤醒词**：App 不做"嘿齐目"、"你好齐目"等端上语音唤醒；必须先按左键（或手机端按钮）才会开始录音。

### 3.3 三种对话气泡

#### 3.3.1 用户拍照气泡

眼镜拍照后，照片实时通过 BLE 缩略图回传到 App 展示。

| 属性 | 内容 |
|------|------|
| 触发方式 | ① 语音转写含关键词兜底触发；② 手机端点【🤳 AI 拍照提问】；③ LLM 判断需拍照后主动下发指令 |
| 气泡内容 | 照片缩略图 + 时间戳 |
| 位置 | 靠右对齐 |
| 角标 | 📷 |

#### 3.3.2 用户语音气泡

按左键（或手机端【🎤 按住说话】）说话后，语音经 ASR 转写为文字展示。

| 属性 | 内容 |
|------|------|
| 触发方式 | 眼镜左键 / 手机端【🎤 按住说话】 |
| 气泡内容 | 语音转写文字 + 时间戳 |
| 位置 | 靠右对齐 |
| 角标 | 🎤 |
| 状态变化 | 收音中（"🎤 聆听中…X KB"）→ 转写中（增量刷新）→ 静默 3 秒结束、展示完整文字 |

#### 3.3.3 AI 讲解气泡

| 属性 | 内容 |
|------|------|
| 触发方式 | 服务端完成 AI 讲解词生成 |
| 气泡内容 | AI 讲解文字（流式逐字展示）+ 分隔线 + 🔊 重新播放按钮 + 时间戳 |
| 位置 | 靠左对齐 |
| 角标 | 🤖 |
| 说明 | **每个 AI 讲解气泡底部都有独立的【🔊 重新播放】按钮**，点击重播该条讲解语音，不限次数 |

### 3.4 首次使用教程

**目的**：新游客拿到手机后大概率不知道"要按眼镜左键说话"这个核心交互，需要一次简单引导。

## 4. 导出 Tab

导出 Tab 是本次会话数据的**唯一出口**，承载两段独立操作 + 结束游览按钮：

- **段 1 · 导出眼镜照片到本机**：走 WiFi 从眼镜下载原图到 App 本地
- **段 2 · 生成二维码**：把 App 本地照片上传服务端 → 拿 `share_url` → 本地渲染二维码
- **结束游览**：底部按钮，触发归还收尾

两段操作可**独立多次触发**、可**同一会话内产生多个二维码**。每次"生成二维码"都是一份独立的 share_bundle，服务端 7 天有效。

### 4.2 状态计数（顶部）

**眼镜端待导出**：通过监听 `CRPMediaFileChangeListener.onNewMediaFileChanged(CRPMediaFileInfo)` 实时刷新 `getPhotoCount()`，**眼镜每拍新图立即刷**。进入 Tab 3 时额外主动调 `queryNewMediaFile()` 一次兜底。

**已导出到本机**：App 本地会话目录（`getExternalFilesDir("session_{id}/photos")`）下的照片文件数。

**语义澄清**：

- "眼镜端待导出" = SDK 视为"新"的媒体文件数 —— 眼镜端拍了、但尚未被 App 的 `downloadMediaFile` 拉过的
- "已导出到本机" = 已通过段 1 拉到 App 本地缓存的，独立于是否已生成二维码
- **两个数字互补**：拍新图 → 眼镜端 +1；执行段 1 → 眼镜端相应减少、本机 +N

### 4.3 段 1 · 导出眼镜照片到本机

**入口**：Tab 3 上的【导出眼镜照片到本机】按钮。**完全手动触发**（对话过程中不后台偷拉）。

**可点条件**：眼镜端待导出 > 0 且眼镜已连接。

**UI（点击后）**：全屏遮罩，展示：

| 元素 | 说明 |
|------|------|
| 标题 | 「正在从眼镜下载照片…」 |
| 副标题 | "请勿断开眼镜" |
| 进度条 | `已下载 X / Y 张` |
| 单张预览 | 每拉完一张，右上角翻页展示，减少空等焦虑 |
| 放弃按钮 | 允许中途放弃 → 关闭遮罩回 Tab 3，已拉到的原图**保留在 App 本地**（下次点击继续时只补拉未完成的） |

**协议流程**：

1. `enableWifi(CRPWifiType.FILE)` — 眼镜切到文件传输 WiFi
2. `connectWifi()` — 建立连接
3. `downloadMediaFile()` — 拉取眼镜端所有"新"媒体文件
4. 完成后 `disableWifi()` — 释放通道
5. 回 Tab 3，"眼镜端待导出"清零、"已导出到本机"累加
6. `queryNewMediaFile()` 补一次确认状态

**边界处理**：

| 场景 | 处理 |
|------|------|
| WiFi 建连失败 | Toast「眼镜 WiFi 连接失败，请靠近眼镜后重试」，「重试」/「取消」按钮 |
| 单张下载失败 | 自动重试 3 次；仍失败则跳过该张 |
| 全量拉取超时（默认 3 分钟无进度） | 提示「下载超时，是否重试？」 |
| 拉取期间眼镜断开 | 遮罩变提示「眼镜已断开，请重连后继续」；重连后自动续拉未完成的 |
| 段 1 期间游客切 Tab | 遮罩保持展示（结束游览前锁住下载状态），切 Tab 无效 |

### 4.4 已导出照片池（宫格展示）

3 列宫格展示 App 本地已导出的所有原图缩略图。

- 每张右上角有个"×"小按钮，点击可**从本地池删除该张**（用于游客反悔，避免上传时看到不想要的）
- 池空时该区域展示占位提示"点击上方按钮把眼镜照片导出到本机"

**可点条件**：已导出到本机 > 0。

**子流程**（点击后进入全屏子流程）：

| 元素 | 说明 |

| 网格 | 3 列宫格，展示本地池所有照片 |
| 选中态 | 每张右上角勾选框；**默认全选** |
| 计数条 | `已选 X / 共 Y 张` + "全选/全不选" |
| 上限提示 | 已选 = 50 时再勾出现 Toast「最多可选 50 张」 |
| 下限约束 | 已选 = 0 时【下一步】灰显 |

#### 4.5.2 输入手机号

| 元素 | 说明 |
|------|------|
| 标题 | 「输入手机号，用于扫码验证」 |
| 说明文字 | "游客扫码时需输入这个号码的后 4 位。手机号仅用于本次分享验证，我们不保留、不发送短信。" |
| 输入框 | `inputType="numberPassword"`、maxLength=11（防输入法记忆） |

**隐私红线**：手机号变量在 4.5.3 上传请求发出后立即置空，仅内存持有。

#### 4.5.3 上传

**协议流程**（对齐 `share-bundle` API）：

1. `POST /v1/share-bundles` — body 含 `phone` / `expected_photo_count` / `need_vlog`，拿到 `bundle_id` / `token` / `share_url` / `expires_at`
2. 循环 `POST /v1/share-bundles/{bundle_id}/photos` — **并发 3~5 个**，每张带 `sort_order`（0 起递增）和 `sha256`
3. `POST /v1/share-bundles/{bundle_id}/finish` — 全部上传完调一次，激活分享；finish 幂等
4. 收到 `share_url` 后 App 本地用 ZXing 渲染成二维码 → 更新 Tab 3 的 §4.6 二维码区

**上传策略**：

- 并发数 3 ~ 5
- 单张失败：自动重试 3 次（指数退避 1s / 2s / 4s）；仍失败则跳过，最后汇总
- 网络断开：暂停上传 + Toast「网络断开，恢复后自动继续」；sha256 秒传保证不重复计费
- 服务端错误码：
  - `sha256_mismatch (30018)` → 立即重试该张
  - `photo_too_large (30013)` / `invalid_photo_format (30015)` → 跳过、汇总提示
  - `not_authenticated (30001)` / HTTP 401 → 中断，「App 配置异常，联系管理员」
- `upload_incomplete (30016)` → 停在本步，"重试剩余"或"跳过失败张继续"

**UI（上传中全屏遮罩）**：

| 元素 | 说明 |
|------|------|
| 标题 | 「正在上传…」 |
| 进度 | `已上传 X / Y 张` |
| 提示 | "上传完成会自动生成二维码" |
| 失败汇总 | 全部结束后如有失败 → 汇总"X 张未成功，是否重试或跳过？" |

上传成功后自动回 Tab 3，二维码显示在 §4.6 区。

### 4.6 二维码展示区

| 元素 | 说明 |
|------|------|
| 二维码 | 大尺寸（≥ 300dp），内容 = `share_url` |
| 有效期说明 | "有效期至 YYYY-MM-DD HH:mm"（`expires_at` 换算本地时间，**不硬编码"7 天"**）|
| 手机号提示 | "扫码后需输入手机号后 4 位：****XXXX" |
| Vlog 状态 | 勾选 Vlog 时展示"🎬 Vlog 正在服务端生成，扫码后 1 分钟左右可查看"；App 端不轮询状态，展示为静态文案 |
| 【再次生成】小按钮 | 允许用户重新走 §4.5 生成一个新二维码（新旧独立、新旧都可扫）|

**多次生成的行为**：Tab 3 只展示**最新一个**二维码。之前生成过的 share_url 服务端仍保留 7 天，已扫过的游客仍可访问，只是不再在 App 上显示。

**二维码展示时长**：**常驻直到结束游览**。游客可以在对话 Tab 与导出 Tab 之间自由切换，二维码始终留在 §4.6 区，随时切回来都能重新扫。

### 4.7 【结束游览】按钮（底部）

Tab 3 底部固定的一个次要按钮（不是主按钮，颜色比【导出眼镜照片】【生成二维码】弱化）。

**点击流程**：

```
点【结束游览】
  → App 调 queryNewMediaFile() 检查眼镜端待导出数量 N
  → N > 0：弹窗"眼镜上还有 N 张未导出的照片"
      ├─ 【先导出再结束】 → 强制走段 1（4.3）→ 弹窗"要生成二维码带走吗？"
      │     ├─ [生成] → 段 2（4.5）走完 → §5 归还收尾
      │     └─ [不用了] → §5 归还收尾（本机已拉但未生成二维码的图会一起丢）
      └─ 【直接结束，眼镜端照片会丢失】 → 二次确认 → §5 归还收尾
  → N = 0：直接二次确认「确认结束游览？」→ §5 归还收尾
```

**特殊情况**：

- 眼镜断开 → 无法 `queryNewMediaFile`，弹窗提示"请先重新连接眼镜再结束游览"；提供"跳过检查直接结束"兜底（后果自负）
- 本机池已生成过二维码但未点结束游览 → 结束游览不额外提醒（游客明确知道已生成过）；点击后按 N 的值走上面流程

### 4.8 导出 Tab 整体行为约束

| 约束 | 说明 |
|------|------|
| 两段独立 | 段 1（导出到本机）与段 2（生成二维码）完全独立；游客可以只做段 1、也可以只做段 2（如果之前段 1 已经做过）|
| 段 1 需 WiFi、段 2 需数据网 | 段 1 用眼镜 WiFi 通道；段 2 用手机数据网 / 场馆 WiFi |
| 二维码常驻 | 生成后到结束游览前始终展示；同一会话内可重复生成多份，Tab 3 只显示最新一个 |
| Vlog 由服务端异步生成 | App 端只负责 create 时传 `need_vlog`；不查询、不轮询状态 |
| App 内不预览分享内容 | 上传后不在 App 上展示 H5 页；游客必须用自己的手机扫码 |
| App 本地未生成二维码的照片，结束游览时一并丢弃 | 不提醒。游客明确知道"生成二维码 = 带走照片" |

## 5. 归还收尾

**触发**：§4.7 结束游览的所有分支最终都汇合到本节。

**执行顺序**（严格按顺序，前一步失败不阻塞下一步继续，但整体流程内不可退出）：

```
1. 全屏 Loading「正在归还…」（不可交互，防止游客中途操作 / 切 Tab / 返回）
2. POST /sessions/{session_id}/close 关闭服务端会话
   ├─ 成功：继续
   └─ 失败：静默重试 2 次；仍失败记录日志、继续（服务端 heartbeat 超时会兜底关）
3. CRPBleConnection.reset(callback) 重置眼镜
   ├─ onSuccess()：眼镜端媒体清空 + 眼镜自动重启
   ├─ onFailure(code)：记录日志，Toast「眼镜清理未确认，请归还前告知管理员」
   └─ 10 秒无回调超时：视同失败
4. 清 App 本地缓存：
   ├─ 会话目录 getExternalFilesDir("session_{id}") 整个删（含所有已导出的原图）
   ├─ PCM 音频临时文件 audio/pcm/ 整个删
   └─ 内存置空：session_id / bundle_id / token / phone / current_share_url / 已生成的二维码 View 引用
5. 断开眼镜 BLE 连接（disconnect；不 unbind，眼镜重启后自动回连本 App）
6. 全屏 Loading 消失 → 回设备 Tab 的"未开始游览"状态（挂牌页形态）
```

**Step 3 关键说明**：眼镜 SDK 未提供"仅删媒体文件"的接口，`reset()` 是清眼镜本地照片的**唯一手段**，同时完成"眼镜端隐私清理 + 触发重启回连"两件事。

**Step 3 失败兜底**：`onFailure` 或超时时，除了 Toast，还要在设备 Tab 未开始游览状态的顶部保留告警条 ⚠️「上次归还未完成清理，请管理员检查眼镜」，同时禁用【开始游览】按钮直到管理员手动重启眼镜（走 §2.1.4 手动扫描连接即可重置告警）。

## 6. 全局交互约束

### 6.1 通用交互

| 约束 | 说明 |
|------|------|
| 开始游览 | 只能在设备 Tab（未开始游览态）点【开始游览】；上一位归还后眼镜自动回连，本位游客通常无需手动扫描（详见 §2.1）|
| 结束游览 | 只能在导出 Tab 点【结束游览】；点击后按眼镜端未导出数量弹窗询问（详见 §4.7），最终统一走 §5 归还收尾 |
| 会话驻留 | 同一会话内切换 Tab 再返回，对话/导出内容保持不丢失（含已生成的二维码） |
| 眼镜断开 | 对话中断开时弹窗提示；段 1 WiFi 拉图期间断开则暂停等重连；段 2 上传对眼镜连接无要求（数据已在 App 本地）；归还收尾 reset 时必须在线 |
| App 退到后台 | 对话不中断；回前台恢复。**段 1 拉图/段 2 上传期间退后台**：拉图暂停等重连、上传持续（用前台服务保活）；归还收尾 §5 期间用前台服务保活 |
| App 被系统杀死重启 | 回到设备 Tab（挂牌页态）；未 finish 的分享包在服务端保持 `uploading` 状态、不会展示给扫码人；本次 session 内 App 本地已导出但未生成二维码的照片丢失；**眼镜端未 reset** → 按 E-19 处理 |
| 新消息自动滚底 | 对话页用户手动上滑查看历史时不自动滚 |

### 6.2 归还前清理清单

**触发时机**：§5 归还收尾。

**必须清理**（每一项都影响下位游客隐私）：

- [ ] **眼镜端媒体文件**：`CRPBleConnection.reset(callback)`，等 `onSuccess` 或最多 10 秒超时；成功后眼镜自动重启并保留 App 绑定关系（不 unbind），供下位游客自动回连
- [ ] App 本地缓存的本次会话所有原图 & 缩略图（`getExternalFilesDir()` 下 session 目录整个删；含已生成过二维码的和未生成的所有导出照片）
- [ ] App 本地缓存的 PCM 音频文件（`audio/pcm/` 目录）
- [ ] 内存中的手机号变量置 `null`（§4.5.2 输入的号码）
- [ ] 二维码 View 销毁、包含 `share_url` / `bundle_id` / `token` 的 View 引用清空
- [ ] Android 键盘输入历史：§4.5.2 用 `inputType="numberPassword"` 或自建键盘，从源头避免
- [ ] session_id 从内存清空
- [ ] 服务端 `POST /sessions/{session_id}/close` 关闭当前会话
- [ ] 断开眼镜 BLE 连接（软断开；**不 unbind**）

### 6.3 数据与服务端边界

| 类别 | App 本地 | 眼镜端 | 服务端 |
|------|---------|--------|--------|
| 会话上下文（对话文字/AI 音频） | 会话内驻留，归还时清 | — | 一期不落库，close 即丢 |
| 眼镜拍的原图 | 段 1 手动导出到本机后驻留 App，归还时清 | 段 1 完成后 SDK 视为"已导出"、归还 `reset()` 清空 | 仅段 2 上传成功的（≤ 50 张/包）进服务端存储，7 天后惰性过期（文件不物理删）|
| 手机号 | 仅 §4.5.2~4.5.3 短时驻留内存，请求发出即置空 | — | Fernet 加密存 `phone_encrypted`；服务端仅通过后 4 位供扫码验证 |
| 分享包 token / share_url | §4.6 二维码区展示，归还时清 | — | 7 天有效，服务端 `share_bundle` 表持久化；同一 session 可产生多份 bundle，均独立有效 |
| BLE 配对关系 | 保留（不 unbind）| 保留 | — |

### 7.5 结束游览 & 归还收尾

| # | 场景 | 处理 |
|---|------|------|
| E-50 | 点【结束游览】时眼镜断开 | 无法 `queryNewMediaFile`，Toast「请先重新连接眼镜再结束游览」；提供【跳过检查直接结束】兜底 |
| E-51 | 结束游览时眼镜端有未导出 → 游客点【先导出再结束】途中导出失败 | 与 §7.3 一致；导出失败后弹「导出未完成，是否直接结束？（未导出图会丢失）」 |
| E-52 | §5 reset 返回 `onFailure(code)` | 记录日志 + Toast「眼镜清理未确认，请归还前告知管理员」；继续清 App 本地并回设备 Tab 未开始状态；顶部保留 E-19 告警条 |
| E-53 | §5 reset 10 秒无回调超时 | 视同失败，同 E-52 |
| E-54 | §5 reset 时眼镜已断开 | 等 5 秒尝试重连；仍失败同 E-52 |
| E-55 | §5 服务端 `POST /sessions/{id}/close` 失败 | 静默重试 2 次；仍失败则记录日志不阻塞（服务端 heartbeat 超时会兜底关闭）|
| E-56 | 归还收尾期间 App 被系统杀死 | 未 finish 的 bundle 保持 `uploading` 状态、扫码人看到"链接失效"；本次 App 本地数据丢失；**眼镜端未 reset** → 下次启动 App 按 E-19 处理 |

### 8.16 底部 Tab 的 3 种视觉态

Tab 图标 + 文字都根据"是否开始游览"控制启用/禁用：

**未开始游览**（挂牌页态）：

```
├────────────────────────────────────────┤
│  📱设备    💬对话(灰)     📤导出(灰)     │
│  ▔▔▔▔                                  │  ← 设备 Tab 有底部下划线
└────────────────────────────────────────┘
```

**游览中 · 停在对话 Tab**：

```
├────────────────────────────────────────┤
│  📱设备    💬对话        📤导出          │
│              ▔▔▔▔                       │  ← 对话 Tab 高亮
└────────────────────────────────────────┘
```

**游览中 · 停在导出 Tab**：

```
├────────────────────────────────────────┤
│  📱设备    💬对话        📤导出          │
│                          ▔▔▔▔          │  ← 导出 Tab 高亮
└────────────────────────────────────────┘
```

游客在游览中可以自由在 3 个 Tab 之间切换。归还收尾期间（§8.13）底部 Tab **完全隐藏**，防止误操作。
