# 分享二维码联调说明

APP 的“选择照片 → 输入手机号 → 上传 → 生成二维码”对接服务端
`feat/recap-photos-vlog` 分支的以下接口：

- `POST /v1/share-bundles`
- `POST /v1/share-bundles/{bundle_id}/photos`
- `POST /v1/share-bundles/{bundle_id}/finish`

## 构建配置

生产 API 地址仍默认为 `http://115.190.147.152:8787`。联调包通过 Gradle 属性或同名环境变量覆盖地址并注入共享密钥，密钥不进入仓库：

```bash
./gradlew \
  -PQIMU_API_BASE_URL=http://192.168.1.10:8787 \
  -PQIMU_SHARE_APP_TOKEN='<与服务端 APP_SHARED_SECRET 相同的值>' \
  :app:assembleDebug
```

也可以设置环境变量 `QIMU_API_BASE_URL`、`QIMU_SHARE_APP_TOKEN` 后构建。未注入密钥的安装包仍可使用导览功能，但在分享页会明确提示管理员重新生成联调包，不会发送无鉴权请求。

## 服务端前置条件

服务端需要完成数据库迁移，并配置 `APP_SHARED_SECRET`、`PHONE_ENCRYPTION_KEY`、`PHONE_HASH_SALT`、`SHARE_ACCESS_SECRET` 和对手机可访问的 `PUBLIC_BASE_URL`。

API 与 Vlog Worker 是两个进程：

```bash
cd '/Users/linxun/Claude Code Development/ai-guided'
./run.sh backend
./run.sh backend worker
```

`PUBLIC_BASE_URL` 不能写 `localhost`，否则二维码中的 H5 地址只在服务端本机可访问。手机与联调服务在同一局域网时，应使用服务端电脑的局域网 IP；线上环境应使用 HTTPS 域名。

## 验收链路

1. APP 导出眼镜照片，选择 1–50 张，可选 Vlog。
2. APP 先流式计算 SHA-256 并合并内容完全相同的重复照片，再按唯一照片数创建 bundle；创建成功后随即清空手机号输入。
3. APP 以 4 路并发上传照片，传 `sort_order` 与 SHA-256；网络或 5xx 最多重试 3 次。
4. 全部上传成功后调用 `finish`，用返回的 `share_url` 本地生成二维码。
5. 游客手机扫码，输入手机号后 4 位，在 H5 查看/下载照片。
6. 开启 Vlog 时，H5 先显示生成中；Worker 完成后页面更新为视频播放器。
7. APP 结束导览后，现有归还流程清空本机照片、选择状态和分享上下文。
