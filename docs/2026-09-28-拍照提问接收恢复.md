# 拍照提问图片接收恢复

## 现场证据

2026-09-28，用户反馈眼镜有拍照反应，App 提示未收到图片。该提示来自
`DialogueFragment` 等待 SDK 图片回调的 10 秒定时器，发生在上传和 AI 识图之前。

读取手机 App 私有目录中的历史拍照文件，仅检查文件长度、JPEG 标记和解码结果：
存在缺少 JPEG 结束标记的截断文件，以及一个带结束标记但解码报错的文件。
之后三次手动复测成功，日志中的图片帧分别连续到达 49、48、47 帧并收到结束包；
第一次从发出拍照指令到文件完成约 2.8 秒。没有抓到原始中断现场，不能据此
判定最初是无线链路、固件还是 SDK 分包解析导致的丢失。未修改 10 秒超时值。

## 已修复的接收恢复缺口

当前依赖 `my_galsses_sdk_1.0.0_20260720_release.aar`：

- `setAiDialogueListener(null)` 只清监听器，不清图片组装单例。
- 图片没有结束包时，单例仍保存旧文件写入流和最后帧序号。
- 重试的第 1 帧会被当成重复首帧丢弃，后续帧可能接到旧文件后面。
- 缺片时 SDK 会忽略不连续帧，但结束包仍可能触发一个不完整文件的回调。

`MoyoungAiImageReceiver` 将对该版本内部组装器的调用集中隔离：在组装器锁内
先移除监听器，再调用其结束方法关闭旧写入流、归零帧号，最后安装新监听器。
开始、失败、取消和完成都经过此边界，丢弃旧数据时不会给业务发成功回调。
未修改 AAR 二进制；升级 SDK 时必须复核内部接口并运行该适配器的设备测试。

图片回调进入上传前，`CapturedJpeg` 检查 JPEG 起止标记。缺失时显示
“眼镜图片传输不完整，请重试”；超时显示“眼镜图片接收超时，请重试”。
该检查只能验证传输边界，不能证明所有压缩数据均正确，也不能补回丢失分片。
协议没有每次拍照的请求 ID，因此这项修复也不能完全区分跨请求晚到的完整照片。

新增日志仅记录操作序号、阶段、耗时和文件字节数，不记录照片内容、文件路径、
会话标识或鉴权信息。后续若再失败，可用这些日志与 SDK 的帧号/结束包对应定位。

## 验证

- JVM 测试：完整边界、截断、空文件、缺失文件和非 JPEG 数据。
- Android 测试使用实际 AAR 的图片组装器及 AI 回调分发，仅替代 BLE 连接对象：
  超时后重试、清理后的晚到分片、同次拍照重复首帧、缺少中间帧。
- 真机无线传输是否稳定需安装修复包后继续验证；修改前连续成功不算修改后的验收。

本次生产环境配置的 debug 构建、110 项 JVM 测试和 lint 均通过；新增的 4 项
SDK 接收回归测试在 Android 35 模拟器通过。lint 仍有 184 条 warning、0 个 error。
