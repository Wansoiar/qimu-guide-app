# 设备初始化与运营配置服务端接口

> 状态：APP 端已按本契约接入 `MockProvisioningApi`，服务端尚未实现。
>
> APP 分支：`feat/device-provisioning`
>
> 目标服务端分支：`feat/recap-photos-vlog`

## 1. 范围和原则

本接口组负责：

1. 运营人员身份验证。
2. 校验运营人员录入的手机 SN，并查找历史设备身份。
3. 获取该运营人员有权限配置的场馆。
4. 将一台手机 APP、一副眼镜和一个场馆原子绑定。
5. 为已初始化 APP 签发独立设备凭证。
6. 运营人员重置设备，撤销凭证并解除绑定。

设备初始化信息存 PostgreSQL，不使用对象存储。照片、缩略图和 Vlog 才使用对象存储。

不能复用照片分享的 App Token，也不能继续使用当前无鉴权的
`POST /v1/admin/devices/report` 作为正式初始化接口。

## 2. 身份定义

| 字段 | 含义 | 唯一性 |
|---|---|---|
| `phone_sn` | 运营人员从手机设置、机身或资产标签录入的手机 SN；标准化为大写 | 手机设备长期唯一，服务端唯一索引 |
| `install_id` | APP 首次运行生成并加密保存的 UUID；重置时保留，卸载后变化 | 当前安装唯一 |
| `android_id_hash` | `ANDROID_ID` 的 SHA-256 | 辅助风控字段，不参与设备主键判定 |
| `device_id` | 服务端生成的手机设备 UUID/业务 ID；APP 更新、卸载重装后保持不变 | 全局唯一 |
| `glasses_id` | 当前使用标准化 BLE MAC；格式 `AA:BB:CC:DD:EE:FF` | 全局唯一 |
| `venue_id` | 服务端场馆 UUID | 引用 `venue.id` |

如果眼镜 SDK 后续能提供不可变硬件 SN，应将 SN 升级为 `glasses_id`，MAC 改为
`ble_mac`。上线前必须用真机验证 MAC 在眼镜重启、手机重启及另一台手机扫描时保持一致。

`phone_sn` 是跨 APP 更新、卸载重装和恢复出厂的设备找回键，`device_id` 仍是服务端
对外业务主键。服务端必须按 `phone_sn` 恢复原 `device_id`，不得按 `install_id`、
`ANDROID_ID`、眼镜或场馆重新生成手机设备。SN 属于敏感设备标识，只能通过 HTTPS
上传，不得写入普通业务日志；运营页面和审计日志建议默认脱敏展示。

## 3. 认证模型

- 初始化和重置使用运营账号密码，服务端签发 15 分钟的
  `provisioning_token`。
- Token 只允许调用本文件中的 provisioning 接口，不能调用完整运营后台接口。
- Token 必须包含 `operator_id`、`roles`、`venue_scope`、`exp` 和 `type=provisioning`。
- 只有 `device_operator`、`venue_admin` 或 `super_admin` 可以初始化设备。
- 登录失败需要限流和账号锁定；错误信息不能暴露账号是否存在。
- APP 不保存运营密码和 provisioning token。初始化完成后只加密保存设备凭证。

## 4. 通用约定

请求：

```http
Content-Type: application/json
X-Request-Id: req_uuid
```

响应沿用现有 Envelope：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "req_uuid"
}
```

涉及写入的接口必须记录操作日志，并支持幂等。初始化请求同时传
`Idempotency-Key` 请求头，推荐值为 `install_id`。

## 5. 接口

### 5.1 运营人员登录

`POST /v1/device-provisioning/login`

无需已有 Token。

请求：

```json
{
  "username": "operator",
  "password": "********",
  "install_id": "31d59176-f4e0-471f-bd9c-cbb38fd95fe1",
  "app_version": "1.1.1"
}
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "provisioning_token": "prv_xxx",
    "expires_in": 900,
    "operator": {
      "id": "uuid",
      "display_name": "前台小张",
      "roles": ["device_operator"]
    }
  },
  "request_id": "req_uuid"
}
```

### 5.2 校验手机 SN 并查询历史设备

`POST /v1/device-provisioning/phone-identities/resolve`

```http
Authorization: Bearer prv_xxx
```

请求：

```json
{
  "phone_sn": "R8Y1234ABC"
}
```

服务端先执行 `trim + uppercase`，只接受 4–64 位字母、数字、点、短横线和下划线。
该接口需要运营 Token，避免未登录用户枚举设备资产。已存在时返回历史设备和场馆；
不存在时返回标准化 SN，后续初始化接口才正式创建设备记录。
如果历史设备不在当前运营人员的 `venue_scope` 内，不得返回设备详情，应返回
`phone_sn_out_of_scope`，由更高权限运营人员处理。

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "phone_sn": "R8Y1234ABC",
    "existing": true,
    "device_id": "dev_uuid",
    "current_venue": {
      "id": "61f1f93d-fe42-49d0-b392-bcbf9cd1c13d",
      "code": "NAMOC",
      "name": "中国美术馆",
      "address": "北京市东城区五四大街 1 号"
    }
  },
  "request_id": "req_uuid"
}
```

新 SN 返回 `existing=false`，`device_id` 和 `current_venue` 为 `null`。

### 5.3 获取可配置场馆

`GET /v1/device-provisioning/venues`

```http
Authorization: Bearer prv_xxx
```

仅返回 `status=active` 且在当前运营人员 `venue_scope` 内的场馆：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [
      {
        "id": "61f1f93d-fe42-49d0-b392-bcbf9cd1c13d",
        "code": "NAMOC",
        "name": "中国美术馆",
        "address": "北京市东城区五四大街 1 号",
        "config_version": 12
      }
    ]
  },
  "request_id": "req_uuid"
}
```

### 5.4 初始化设备

`POST /v1/device-provisioning/initialize`

```http
Authorization: Bearer prv_xxx
Idempotency-Key: 31d59176-f4e0-471f-bd9c-cbb38fd95fe1
```

请求：

```json
{
  "install_id": "31d59176-f4e0-471f-bd9c-cbb38fd95fe1",
  "android_id_hash": "sha256_hex",
  "phone": {
    "serial_number": "R8Y1234ABC",
    "serial_number_source": "operator_input",
    "model": "HUAWEI LYA-AL00",
    "os_version": "Android 12",
    "app_version": "1.1.1"
  },
  "glasses": {
    "id": "AA:BB:CC:DD:EE:FF",
    "id_type": "ble_mac",
    "name": "V03 眼镜"
  },
  "venue_id": "61f1f93d-fe42-49d0-b392-bcbf9cd1c13d"
}
```

服务端必须在一个数据库事务中：

1. 校验运营人员对 `venue_id` 有权限。
2. 按标准化 `phone.serial_number` 查找手机设备；命中时恢复原 `device_id` 并更新最新 `install_id`，未命中时才创建新设备。
3. 创建或获取眼镜设备。
4. 检查该眼镜是否已绑定其他有效手机。
5. 建立手机—眼镜当前绑定。
6. 保存场馆归属并生成独立设备凭证。
7. 写入初始化操作日志。

响应中的 `device_credential` 只返回一次，服务端只保存哈希：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "device": {
      "id": "dev_uuid",
      "phone_sn": "R8Y1234ABC",
      "install_id": "31d59176-f4e0-471f-bd9c-cbb38fd95fe1",
      "device_credential": "dvc_secret_returned_once"
    },
    "glasses": {
      "id": "gls_uuid",
      "hardware_id": "AA:BB:CC:DD:EE:FF",
      "name": "V03 眼镜"
    },
    "venue": {
      "id": "61f1f93d-fe42-49d0-b392-bcbf9cd1c13d",
      "code": "NAMOC",
      "name": "中国美术馆",
      "address": "北京市东城区五四大街 1 号"
    },
    "config": {
      "version": 12
    },
    "provisioned_at": "2026-08-10T10:00:00Z"
  },
  "request_id": "req_uuid"
}
```

相同 `phone_sn` 无论 `install_id`、`android_id_hash`、眼镜或场馆是否变化，都必须返回同一
`device_id`，不得创建重复手机设备记录。绑定变化仍需校验运营权限并保留历史记录。
重复提交相同 `install_id + glasses_id + venue_id` 时不得创建重复绑定。
如果旧凭证已经返回过，幂等重试可以在短时窗口内重放加密响应，或签发新凭证并立即撤销旧凭证。

### 5.5 已初始化设备握手

`POST /v1/devices/handshake`

APP 后续冷启动使用，不携带运营 Token：

```json
{
  "device_id": "dev_uuid",
  "install_id": "31d59176-f4e0-471f-bd9c-cbb38fd95fe1",
  "timestamp": 1786336800,
  "nonce": "random_uuid",
  "signature": "hmac_sha256(device_credential, canonical_body)"
}
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "device_token": "dev_xxx",
    "expires_in": 86400,
    "device_status": "active",
    "config_version": 12
  },
  "request_id": "req_uuid"
}
```

### 5.6 拉取当前设备配置

`GET /v1/devices/config`

```http
Authorization: Bearer dev_xxx
If-None-Match: "config-12"
```

响应至少包含设备当前绑定，不能只返回租赁 Session：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "device_id": "dev_uuid",
    "status": "active",
    "glasses": {
      "id": "gls_uuid",
      "hardware_id": "AA:BB:CC:DD:EE:FF"
    },
    "venue": {
      "id": "61f1f93d-fe42-49d0-b392-bcbf9cd1c13d",
      "code": "NAMOC",
      "name": "中国美术馆",
      "address": "北京市东城区五四大街 1 号"
    },
    "config_version": 12,
    "runtime_config": {}
  },
  "request_id": "req_uuid"
}
```

配置未变化时可返回 HTTP 304。APP 离线策略另行确认；在确认前，不应把本地缓存无限期视为有效配置。

### 5.7 重置设备

`POST /v1/device-provisioning/devices/{device_id}/reset`

```http
Authorization: Bearer prv_xxx
```

请求：

```json
{
  "reason": "venue_reconfiguration",
  "expected_glasses_id": "AA:BB:CC:DD:EE:FF"
}
```

服务端必须：

1. 校验运营权限。
2. 如果设备存在进行中的租赁/导览，返回冲突，不执行任何修改。
3. 撤销所有设备 Token 和设备凭证。
4. 结束当前手机—眼镜绑定，但不删除手机、眼镜及历史绑定记录。
5. 保留手机设备的 `device_id` 和 `phone_sn`，再次初始化时恢复同一设备身份。
6. 写入操作者、旧场馆、旧眼镜和原因的审计日志。

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "device_id": "dev_uuid",
    "status": "unprovisioned",
    "reset_at": "2026-08-10T11:00:00Z"
  },
  "request_id": "req_uuid"
}
```

APP 只有收到成功响应后才清除本地凭证并回到“连接眼镜”页面。接口失败时本地状态必须保持不变。

## 6. 建议错误码

| HTTP | code | message | APP 行为 |
|---|---:|---|---|
| 400 | 10901 | `invalid_glasses_id` | 保留页面，提示重新连接眼镜 |
| 401 | 10902 | `invalid_operator_credentials` | 显示通用账号或密码错误 |
| 401 | 10903 | `provisioning_token_expired` | 返回运营登录步骤 |
| 403 | 10904 | `venue_out_of_scope` | 刷新场馆列表 |
| 404 | 10905 | `venue_not_found` | 刷新场馆列表 |
| 409 | 10906 | `glasses_already_bound` | 提示联系管理员解除旧绑定 |
| 409 | 10907 | `active_session_exists` | 禁止重置，先结束导览 |
| 409 | 10908 | `device_binding_changed` | 刷新配置后重新确认 |
| 410 | 10909 | `device_revoked` | 清除本地凭证，回到初始化流程 |
| 429 | 10910 | `too_many_attempts` | 显示剩余锁定时间 |
| 400 | 10911 | `invalid_phone_sn` | 保留 SN 步骤并提示检查输入 |
| 403 | 10912 | `phone_sn_out_of_scope` | 不展示历史设备信息，提示联系管理员 |

## 7. 数据模型最低要求

现有 `device` 表可继续保存手机和眼镜资产，但建议新增绑定历史表：

```sql
CREATE TABLE device_glasses_binding (
    id UUID PRIMARY KEY,
    phone_device_id UUID NOT NULL,
    glasses_device_id UUID NOT NULL,
    venue_id UUID NOT NULL,
    bound_by UUID NOT NULL,
    bound_at TIMESTAMPTZ NOT NULL,
    unbound_by UUID,
    unbound_at TIMESTAMPTZ,
    unbind_reason TEXT
);
```

还需要为手机设备补充 `phone_sn`、`install_id`、`android_id_hash`、`credential_hash`、
`provisioned_at`、`provisioned_by`、`config_version`、`app_version` 和 `status`。
数据库应保证同一时刻一台手机最多绑定一副眼镜，一副眼镜最多绑定一台有效手机。
标准化后的 `phone_sn` 应建立唯一索引。历史 `install_id` 可另表留存，用于审计重装事件。

`ProvisioningApiProvider` 中替换实例即可。UI、状态存储和重置动线不需要改写。

## 9. 服务端验收用例

1. 无权限人员无法获取场馆或初始化设备。
2. 运营人员只能看到权限范围内的 active 场馆。
3. 同一初始化请求重复发送不会创建重复设备或绑定。
4. 同一个 `phone_sn` 在 `install_id` 或 `android_id_hash` 变化后，初始化仍返回原 `device_id`。
5. 已绑定其他手机的眼镜返回 409。
5. 初始化响应后，设备握手和配置拉取成功。
6. 重置立即使旧设备凭证和 Token 失效。
7. 进行中的导览不能重置。
8. 初始化、换绑、重置均可在操作日志中追溯操作者和前后状态。
